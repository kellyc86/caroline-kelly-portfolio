Does the ULEZ show up in London's air?

I owned the Silver layer of a Medallion pipeline that joins seven London datasets into a borough-month fact table, built to test whether the ULEZ, weather, tree cover and deprivation explain differences in NO2 and PM2.5.

RoleGroup of four. I owned pipeline_silver.ipynb, the Spark cleaning of the 102 MB LAQN readings file
StackPython, Spark, Parquet, DuckDB, MongoDB, TinyDB, GeoPandas, SciPy
DataSeven sources: LAQN hourly readings and episodes, Open-Meteo, IMD 2019, GLA tree canopy 2024, TfL congestion charge counts, ULEZ boundary
CodeGroup repository, private. My Silver-layer notebook available on request.
Group project. The repository is hosted by a group member. The Bronze and Gold layers, the document stores and the analysis were shared across the four of us.

Problem

My part was the Silver layer: Spark cleaning of the 102 MB LAQN readings file and six smaller sources into seven validated Parquet datasets that every later stage reads from. The sources arrived in different formats, so the joins could not be trusted until the cleaning was.

The question underneath: did stations inside the ULEZ show lower NO2 in 2024?

Skills

  • Spark cleaning: ~925,000 hourly readings, schema enforcement, Title Case borough names as join keys
  • Validation gates: row counts, join-key null rates, borough name consistency, before any Gold computation
  • Medallion: Bronze raw, Silver Parquet, Gold DuckDB SQL over Parquet
  • Tests: GeoPandas point-in-polygon, Welch's t-test, Pearson correlation

Results

22.85 vs 26.57mean NO2 μg/m³ inside against outside the ULEZ, not significant (p = 0.121)
+1.36μg/m³ NO2 on inversion days
r = −0.026tree canopy against PM2.5; deprivation p = 0.841

The pipeline

All downstream stages read from Silver rather than re-processing Bronze, which keeps transformations auditable.

BronzeRaw, as received
SilverSpark cleaning to Parquet, three checks
NoSQLEpisodes in TinyDB and MongoDB
GoldDuckDB borough-month fact table
AnalysisULEZ flag, inversion flag, t-tests

What a label would do with this

Consumption data arrives the same way, many feeds in many shapes, and a Silver layer with schema enforcement and row-count checks is what stops a silent type coercion corrupting every release-week join downstream.

Limits. Only one monitoring station fell outside the ULEZ boundary in 2024, so the comparison is inconclusive. PM2.5 exists for only 37 per cent of borough-months, so borough-level correlations are unreliable. Proposed next step: a 2023 versus 2024 difference-in-differences around the August 2023 ULEZ expansion.
