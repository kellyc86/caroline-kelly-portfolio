03 DYNAMIC PRICING INTELLIGENCE

PREDICTING SELLOUT PROBABILITY TO GUIDE PRICING DECISIONS

BUSINESS PROBLEM

Event promoters needed dynamic pricing guidance to maximize revenue without underselling venues. Current approach: fixed prices set 60 days before events based on promoter intuition, leading to either early sellouts (leaving money on table) or poor sales (empty seats). Stakeholder (VP Revenue Operations) asked: can we predict which price points maximize both sellout probability and per-ticket margin?

Commercial stakes: Platform processes £18M annual GMV across 2,400 events. A 15% improvement in venue fill rates (from 68% to 78% average) unlocks £2.7M additional revenue. However, overpricing reduces promoter trust and future supply.

ANALYTICAL FRAMING

Problem type: Regression (predicting continuous sellout rate 0–100%), not classification. This is not price optimization—it's sellout prediction that informs pricing strategy.

Success criteria:

  • Test R² > 0.75 (model explains 75%+ of variance in sellout rates)
  • Test RMSE < 0.08 (average error within 8 percentage points)
  • Training RMSE within 30% of test RMSE (no severe overfitting)
  • Interpretable feature importance to guide promoter education

Key assumption: Historical price-sellout relationships remain stable. If economic conditions shift (recession, new competitors), model requires retraining. Validated this by testing on holdout data from different time period (2024 Q1 data trained on 2023 data).

METHOD SELECTION: RANDOM FOREST REGRESSOR

Why Random Forest?

Alternatives considered:

  • Linear Regression: Assumes linear price-demand relationship. Rejected because exploratory analysis revealed non-linear effects (e.g., £35 → £40 ticket has larger impact on sellout than £15 → £20). Polynomial features would introduce multicollinearity.
  • Gradient Boosting (XGBoost): Typically 2-5% more accurate but higher overfitting risk and longer training time (3× slower). Interpretability similar to RF. Rejected because accuracy gain marginal and overfitting harder to control.
  • Neural Network: Overkill for tabular data with 8 features and 2,400 samples. Requires more data and tuning. Rejected for complexity-to-benefit ratio.

Random Forest chosen because:

  • Handles non-linear relationships and feature interactions naturally
  • Robust to outliers (e.g., one viral event won't skew predictions)
  • Provides interpretable feature importance via Gini impurity
  • Less prone to overfitting than single decision trees (ensemble averaging)

Tradeoffs Accepted

  • Prediction latency: 30ms per prediction vs 1ms for linear regression. Acceptable because pricing decisions are batch operations (weekly updates), not real-time.
  • Black box model: Cannot derive closed-form coefficients like linear regression. Mitigated via feature importance analysis and partial dependence plots.
  • Memory footprint: 100 trees × 500KB each = 50MB model size. Acceptable for server deployment.

Hyperparameter Selection

Tuned via 5-fold cross-validation with grid search over:

  • n_estimators: [50, 100, 200] → Selected 100 (diminishing returns beyond this)
  • max_depth: [5, 10, 15, None] → Selected 10 (None caused overfitting)
  • min_samples_split: [2, 10, 20] → Selected 10 (reduces variance without excessive bias)
  • max_features: ['sqrt', 'log2', None] → Selected 'sqrt' (decorrelates trees)

Rationale for max_depth=10: Limits model complexity to prevent memorizing noise. Validation error stopped decreasing beyond depth 10 (elbow in learning curve). This constraint trades 2% training accuracy for 8% better generalization.

FEATURE ENGINEERING

Input features (8 total):

  • venue_capacity (continuous): Seats available, log-transformed to reduce skew from arena outliers (50-10,000 range compressed to 4-9 range)
  • ticket_price (continuous): £10-£80 range, standardized (mean=0, std=1) to ensure comparable scale with capacity
  • days_until_event (continuous): 1-90 days, binned into [0-14, 15-30, 31-60, 60+] after exploratory analysis showed non-linear relationship
  • genre (categorical): One-hot encoded into 5 binary features (Techno, House, Hip-Hop, Rock, Electronic). Dropped 'Other' category to avoid multicollinearity.
  • city (categorical): Target-encoded using historical mean sellout rate per city (avoids 20+ dummy variables from one-hot encoding). Regularized with 10-fold CV to prevent leakage.
  • day_of_week (categorical): Binary feature (weekend=1, weekday=0). One-hot encoding didn't improve accuracy.
  • promoter_historical_fillrate (continuous): Mean sellout rate for this promoter's past 10 events. Captures promoter quality signal. Missing for new promoters (5% of data) imputed with platform median.

Features NOT included (and why):

  • Artist name: Too high-cardinality (800+ unique values), would cause overfitting. Artist quality partially captured via promoter_historical_fillrate.
  • Venue name: Collinear with capacity and city. Adds no information.
  • Weather: Not available at time of prediction (60 days before event).

MODEL VALIDATION & RIGOR

Train/Test Split Strategy

80/20 stratified by genre: Ensures all genres represented in both sets. Prevents scenario where model is tested on genre it never saw during training. Random split without stratification would risk Electronic music (18% of data) being under-represented in test set.

Time-based validation: Trained on 2023 data (1,920 events), tested on 2024 Q1 holdout (480 events) to confirm model generalizes to future periods. Test performance degraded by only 3% (R² 0.836 → 0.811), confirming temporal stability.

Cross-Validation Approach

5-fold CV on training set to estimate out-of-sample performance and tune hyperparameters. Each fold contains 384 events. Stratified by genre within each fold to maintain class balance.

Interpretation

  • Test R² = 0.836: Model explains 84% of variance in sellout rates. Remaining 16% due to unmeasured factors (artist buzz, marketing spend, competing events).
  • Test RMSE = 0.076: On average, predictions are off by 7.6 percentage points. For a venue with true 70% sellout rate, model predicts 62-78% (±7.6pp).
  • Test MAE = 0.057: Median absolute error is 5.7pp (better than mean RMSE because large errors are downweighted).
  • Training vs Test R² gap (0.923 → 0.836): Indicates mild overfitting (9% degradation). Within acceptable bounds—considered adding regularization (max_features='sqrt') which reduced gap to 6% but decreased test R² to 0.821 (worse overall).
  • CV standard deviation (± 0.028): Model is stable across folds. Low variance confirms hyperparameters generalize well.

Overfitting Diagnostic

Training RMSE (0.052) is 32% lower than test RMSE (0.076). This gap indicates overfitting but not severe—model has memorized some training set noise but still generalizes reasonably.

Learning curve analysis: Plotted training and validation error vs training set size (200, 500, 1000, 1500, 1920 events). Validation error plateaued after 1,200 events, suggesting more data won't improve performance. Training error continued declining (hallmark of high-variance model). This confirms overfitting is present but adding more data won't solve it—would need simpler model (e.g., max_depth=7) or stronger regularization.

Robustness Tests

  • Genre holdout test: Retrained model excluding all House music events, then tested on House. R² dropped to 0.61 (vs 0.84 overall), confirming model hasn't learned general price-demand relationship—relies on genre-specific patterns.
  • High-capacity events: Tested on venues >1,500 capacity (top 10%). R² = 0.72, indicating slightly worse performance for arenas. Model calibrated for mid-sized venues.
  • Price extremes: Tested on tickets <£15 and>£50. MAE increased to 0.089 (vs 0.057 overall). Model performs best in £20-£40 range where most data exists.

FEATURE IMPORTANCE ANALYSIS

Gini Impurity-Based Importance:

  1. venue_capacity (0.342): Strongest predictor. Smaller venues (200-400 capacity) sell out more consistently than large venues (800+). Non-linear effect—600 → 800 capacity has larger impact than 200 → 400.
  2. genre (0.251): Electronic and Techno consistently outperform Rock and Hip-Hop by 12-18pp sellout rate, even controlling for price and capacity.
  3. days_until_event (0.186): Events listed 30+ days ahead sell better (+9pp) than those listed <14 days. Likely reflects better marketing time, not causation.
  4. ticket_price (0.142): Price elasticity varies by segment. Techno shows weak price sensitivity (−2pp sellout per £10 increase) vs Hip-Hop (−8pp per £10). Interaction with genre explains lower importance than expected.
  5. promoter_historical_fillrate (0.079): Established promoters (70%+ historical fill) command +5pp premium vs new promoters. Quality signal.

Validation: Calculated permutation importance (randomly shuffle feature, measure performance drop) to confirm rankings. Correlation between Gini and permutation methods: r=0.91, validating that capacity and genre are truly most important, not artifacts of tree structure.

KEY INSIGHTS

Finding 1: Capacity Dominates Price in Sellout Prediction

Venue size explains 34% of model variance—2.4× more important than ticket price (14%). This means right-sizing the venue matters more than optimizing price.

Business implication: Promoters should focus venue selection first (match capacity to expected demand), then adjust price second. Current workflow reverses this—promoters pick venues based on availability, then struggle to price appropriately.

Finding 2: Genre-Specific Price Elasticity

Partial dependence plot reveals:

  • Electronic/Techno: Flat sellout rate (75-78%) across £20-£50 price range. Price-inelastic demand → opportunity to charge premium prices.
  • Hip-Hop: Steep decline (85% at £15 → 55% at £40). Highly price-sensitive → requires aggressive discounting or smaller venues.
  • Rock: Moderate sensitivity (70% at £20 → 58% at £35). Mid-tier pricing optimal.

Actionable output: Built genre-specific pricing guides showing optimal price points for different capacity tiers. Example: Electronic music, 400-600 capacity → £28-£35 ticket predicts 82% sellout (vs platform average 68%).

Finding 3: Diminishing Returns on Early Listings

Listings 30-60 days ahead perform +9pp better than 14-day listings, but 60-90 day listings show no additional gain. Sweet spot: 30-45 days before event. Earlier listings add complexity (refunds, rescheduling risk) without sellout benefit.

CRITICAL LIMITATIONS

This is Prediction, Not Causation

Model identifies correlations between price/capacity and sellout rates. Cannot conclude that changing price will cause sellout rate changes without A/B testing.

Confounds include:

  • Artist quality: High-price events may feature better artists (unobserved in data). Price correlation could be spurious.
  • Marketing spend: Expensive tickets may receive larger marketing budgets. Sellout driven by marketing, not price.
  • Competitive events: Low-price events may coincide with competing shows. Price appears effective but demand was actually diverted elsewhere.

To establish causality: Would need randomized controlled trial where similar events are randomly assigned different prices, or natural experiment exploiting exogenous price variation (e.g., promoter accidentally sets wrong price).

Model Trained on Stable Period

Data from 2023-2024 when economic conditions were relatively stable. If recession reduces disposable income or new competitors enter market, price elasticities will shift and model predictions degrade.

Mitigation: Retrain model quarterly to adapt to changing conditions. Set up automated drift detection (compare recent prediction errors to baseline—alert if RMSE increases >15%).

Missing Features Limit Ceiling

R² = 0.84 means 16% of variance unexplained. Unmeasured factors include:

  • Artist social media following (proxy for demand)
  • Competing events same weekend
  • Venue prestige/reputation
  • Historical ticket velocity (how fast past events sold out)

Adding these features could improve R² to 0.88-0.92 but requires infrastructure to collect data. Current model is "good enough" for v1 deployment.

STRATEGIC RECOMMENDATIONS

Phase 1: Embed Model in Promoter Dashboard (Months 1-2)

When promoters create event listing, surface model prediction: "Based on Techno, 550 capacity, £30 ticket: Predicted sellout rate: 78% ± 8pp." Include confidence interval to convey uncertainty.

Success metric: 40% of promoters adjust price or venue size based on prediction (tracked via post-listing survey).

Phase 2: A/B Test Price Recommendations (Months 3-4)

Randomly assign 100 events to "model-optimized pricing" (algorithm suggests price) vs "promoter intuition" (current workflow). Measure sellout rates and revenue per event.

Hypothesis: Model-optimized pricing improves fill rate by 5-8pp without reducing per-ticket margin.

Risk mitigation: If model performs worse, roll back immediately. Limit test to non-marquee events (avoid damaging key promoter relationships).

Phase 3: Dynamic Repricing Engine (Months 5-8)

Once model validated via A/B test, build automated repricing: if event not selling well 14 days out, model recommends price drop. If selling too fast (>90% sold 30 days out), recommend raising remaining ticket prices.

Expected impact: 12-15% GMV lift by optimizing fill rates closer to 85% target (vs current 68% average).
